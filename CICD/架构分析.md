## 二、CI/CD 流水线设计

### 触发规则

```
push master（HTML 文件变更）  → 校验 → 部署
PR → master                    → 校验（不部署）
```

### Stages

```
┌──────────┐     ┌──────────┐
│  Stage 1 │────▶│  Stage 2 │
│  Validate│     │  Deploy  │
└──────────┘     └──────────┘
  HTML 语法校验    上传到 CloudBase
  文件完整性检查    静态托管
  链接可达性检查    CDN 自动生效
```

### Stage 1 — Validate（校验）

| 检查项 | 工具 | 说明 |
|--------|------|------|
| HTML 语法 | `html5validator` (Python) | 基于 validator.nu，W3C 标准 |
| 文件清单 | Shell | 列出所有 .html 文件及大小 |
| 本地引用 | `grep file://` | 确保无 file:// 残留（应由 CDN 替代） |
| 外部链接 | `curl` 探测 | PR 时检查 tcb.qcloud.la CDN 链接可达性 |

### Stage 2 — Deploy（部署）

| 步骤 | 工具 | 说明 |
|------|------|------|
| 安装 Node 22 | `actions/setup-node@v4` | 运行时 |
| 安装 SDK | `npm install @cloudbase/node-sdk` | 上传依赖 |
| 执行部署 | `scripts/deploy-to-cloudbase.js` | 递归上传所有 .html |
| 记录日志 | GitHub Step Summary | 部署时间/分支/提交信息 |

### 部署脚本逻辑 (`scripts/deploy-to-cloudbase.js`)

```
1. 读取 TCB_SECRET_ID / TCB_SECRET_KEY（从 GitHub Secrets）
2. 递归扫描仓库所有 .html 文件（排除 .git / node_modules / _备份）
3. 逐个上传到 CloudBase 静态托管 /home/ 路径
4. 失败自动重试一次
5. 输出部署清单 & CDN 访问路径
```

## 四、注意事项

1. **图片上传独立处理**：HTML 中 `file://` 本地图片引用需先用 `cloudbase-cdn-upload` 技能上传为 CDN 链接，CI/CD 只负责 HTML 文件部署
2. **静态托管路径**：部署到 `/home/` 目录，保持与仓库的相对路径结构
3. **无构建步骤**：当前项目为纯静态 HTML，无 webpack/vite/build 步骤，流水线跳过 build stage
4. **加构建步骤**：若将来引入构建工具（如 HTML 压缩、CSS 优化），在 `validate` 和 `deploy` 之间插入 `build` job 即可
